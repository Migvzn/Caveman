## 1. CONTEXTE & OBJECTIFS
VAYNORA House est une agence premium de management de créatrices et créateurs de contenu sur les plateformes d'abonnement (OnlyFans, Fansly, MYM, Fanvue) — activité appelée "OFM" (OnlyFans Management). Elle accompagne des créatrices majeures sur : stratégie & branding, marketing & acquisition de trafic, gestion des messages & monétisation, planification de contenu, protection anti-fuite, accompagnement business.
Positionnement : "la maison" haut de gamme, transparente, éthique et protectrice — l'opposé des agences opaques. Signature : « Votre talent. Notre maison. »

L'application a trois briques :
1. Un SITE PUBLIC vitrine, 100 % SFW, élégant, qui convertit (candidatures créatrices, candidatures équipe, contacts).
2. Un ESPACE PRIVÉ "VAYNORA OS" (connexion obligatoire, route /app) : CRM créatrices, recrutement, opérations des chatters, contenu, KPIs, finance, conformité.
3. L'ACADÉMIE VAYNORA, intégrée à l'espace privé : la formation OFM complète de l'agence (19 modules, 141 leçons, quiz, examen final, certificats, coach IA, simulateur de conversation). Le programme est décrit en section 7. La formation complète (texte intégral des 141 leçons, 19 quiz, examen final, 6 parcours) est fournie dans le fichier vaynora-formation-pack.json et s'installe en un clic depuis l'administration de l'Académie (section 6.2, "Installer la formation").

Objectifs mesurables :
- Convertir les visiteuses en candidatures créatrices qualifiées.
- Recruter, former et certifier chatters, managers et recruteurs via l'Académie.
- Piloter toute l'agence depuis un seul outil.

### 6.2 Académie VAYNORA (/app/academie) — la formation OFM intégrée
Structure : LearningPath (parcours) → AcademyModule (modules) → Lesson (leçons) + Quiz (un par module).
Apprenant :
- Catalogue de mes parcours (assignés + ceux dont target_role correspond à mon rôle ou "all") : cartes avec couverture, progression %, prochaine leçon, échéance.
- Page parcours : modules ordonnés avec statut (verrouillé / en cours / validé). Déverrouillage séquentiel : un module s'ouvre quand le précédent est validé (toutes ses leçons terminées + quiz ≥ seuil, défaut 80 %).
- Page module : objectifs, description, leçons cochées si terminées, durée totale, accès au quiz.
- Page leçon : contenu Markdown rendu proprement (react-markdown + remark-gfm : titres, listes, tableaux, citations, gras, cases à cocher), vidéo optionnelle (YouTube/Vimeo/Loom), ressources, encadré "À retenir", barre de progression de lecture, bouton "Marquer comme terminée", précédent/suivant, panneau "Mes notes" (autosave), bouton "Demander au coach IA".
- Quiz : QCM (une ou plusieurs bonnes réponses), vrai/faux, réponse courte (corrigée par IA, cf. 9.3). Explications affichées après soumission. 3 tentatives par 24 h.
- Certificat : quand tous les modules d'un parcours sont validés → Certificate (code "VAY-AAAA-" + 6 caractères), ajout à User.certified_paths, email de félicitations, page imprimable élégante (A4 paysage, fond noir, cadre doré, monogramme, nom, parcours, date, score moyen, code) + vérification publique /verifier/:code.
- Badges (premier module validé, 100 % à un quiz, 7 jours d'apprentissage consécutifs, parcours terminé) et points (leçon 10, quiz réussi 50, 100 % +25) avec classement opt-in.
Administration (owner + manager, /app/academie/admin) :
- CRUD parcours, modules, leçons (éditeur Markdown avec aperçu côte à côte), quiz (éditeur de questions), réordonnancement par glisser-déposer, publier/dépublier.
- Assignation de parcours à des utilisateurs (PathAssignment avec échéance, email d'information).
- Suivi des apprenants : tableau personnes × modules (statut, score, tentatives, retards en rouge), export CSV.
- INSTALLER LA FORMATION (fonction prioritaire, owner) : sur /app/academie/admin, un grand encart "Installer / mettre à jour la formation VAYNORA" avec un sélecteur de fichier .json. Le fichier vaynora-formation-pack.json est lu DANS LE NAVIGATEUR (file.text() puis JSON.parse) — aucun appel IA, aucun envoi externe. Vérifier format === "vaynora-academy-pack", puis afficher un aperçu (stats, liste des modules avec nombre de leçons et de questions, liste des parcours) et un bouton "Installer".
  Format exact du fichier :
  { format, version, title, generated_at, stats { modules, lessons, questions, hours, paths }, overview_md,
    modules: [ { number, title, meta, description, objectives [], order, is_published,
                 lessons: [ { number_label, title, order, content_md, duration_min, key_takeaways [], video_url, resources [] } ],
                 quiz: { title, passing_score, max_attempts_per_day, questions: [ { id, type (single|multiple|true_false|short_answer), prompt, options [], correct [indices 0-based], expected_answer, explanation, points } ] } ou null } ],
    learning_paths: [ { title, slug, target_role, module_numbers [], description, passing_score, is_published } ] }
  Algorithme d'installation (barre de progression + journal ligne par ligne) :
  1. Pour chaque module (dans l'ordre du fichier) : chercher un AcademyModule de même number → le mettre à jour, sinon le créer. Récupérer son id.
  2. Leçons du module : rapprocher les leçons existantes de ce module par order → mettre à jour celles qui existent, créer les nouvelles avec bulkCreate (lots de 25), supprimer uniquement celles absentes du fichier. Renseigner module_id ET module_number. (Ainsi la progression des apprenants n'est jamais cassée.)
  3. Quiz du module : mettre à jour le Quiz existant du module ou le créer (module_id, module_number).
  4. Parcours : pour chaque learning_path, chercher un LearningPath de même slug (mise à jour) ou le créer ; module_ids = ids des modules correspondant à module_numbers, DANS LE MÊME ORDRE ; enregistrer aussi module_numbers.
  5. Enregistrer overview_md, la version et la date d'installation dans SiteSettings (academy_overview_md, academy_pack_version, academy_installed_at).
  6. Résumé final (modules / leçons / quiz / parcours créés ou mis à jour). En cas d'erreur : afficher le module en cause et permettre de relancer. L'installation est idempotente : la relancer ne crée jamais de doublons.
  Ne jamais toucher à LessonProgress, QuizAttempt, Certificate, PathAssignment pendant une installation.
- IMPORT D'UN MODULE (secours ou mise à jour ciblée) : une zone où je colle le texte complet d'un module de la formation OFM au format Markdown → parseur DÉTERMINISTE (code, pas IA) → aperçu (module, leçons, questions) → bouton "Importer". Règles du parseur :
  • Ligne commençant par "# " = titre du module ; retirer le préfixe "Module N — " et utiliser N comme number/order.
  • Lignes "> " juste après le titre = meta (durée, niveau, parcours).
  • Texte entre le titre et le premier "## " = description du module.
  • Chaque section "## Leçon N.M — Titre" = une leçon (number_label N.M, contenu = tout jusqu'au prochain "## "). Toute autre section "## Titre" qui ne commence pas par "Quiz" (ex. "## Atelier pratique — Module 3") devient aussi une leçon portant ce titre.
  • Dans une leçon, un bloc "### À retenir" alimente aussi key_takeaways (une puce = un élément).
  • La section "## Quiz…" contient les questions : chaque question commence par "**Q<n>.**" ; options = lignes "- A) …", "- B) …" ; réponse = ligne "> ✅ Réponse : B — explication" (plusieurs lettres possibles "A, C" → type multiple ; deux options Vrai/Faux → true_false). Sans options → type short_answer, et la ligne "> ✅ Réponse attendue : …" donne la réponse modèle.
  • duration_min d'une leçon = nombre de mots / 200, arrondi à la minute supérieure.
  • Option "Remplacer le module existant de même numéro" (supprime ses leçons et son quiz avant import), puis publie le module.
  • Tolérance : espaces multiples, tirets — – -, retours à la ligne \r\n, lettres minuscules.
  • Si le parseur trouve 0 leçon : bouton secours "Analyser avec l'IA" (InvokeLLM avec response_json_schema).

Vue imprimable.

### 6.9 KPIs & Analytics (/app/kpis)
